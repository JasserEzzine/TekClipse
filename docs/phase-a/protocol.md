# Scientific evaluation protocol

This is a synthetic experiment, not real satellite validation. The original paper is unavailable in the repository, so its numerical targets and methodology cannot be checked. No post-hoc target is presented as an original research requirement.

## Reproduce

From `tekclipse-cloud`, with the pinned environment:

```powershell
python -m pip install -r requirements.txt
python -m pytest -q
python scripts/run_experiment.py --scientific --output results/phase-a
```

The command generates datasets in memory, trains on nominal data, performs validation-only threshold selection, freezes the protocol/source/training fingerprints, and then evaluates independent test runs. It writes JSON, per-run and aggregate comparison CSVs, confusion matrices, ablations, incident results, batch timings and Markdown tables. It adds no runtime dependencies. Scientific duration/seeds come from [protocol.json](protocol.json); the older `--hours`/`--scenario` arguments apply to the historical mode.

To separate stages:

```powershell
python scripts/run_experiment.py --scientific --stage validation --output results/phase-a
python scripts/run_experiment.py --scientific --stage test --output results/phase-a
```

Test-only execution requires the existing frozen validation artifact and rejects changed source, configuration, training fingerprints, calibration fingerprints or fitted thresholds. It refits deterministically on the same **training** data; it never fits or selects thresholds on the test data. Re-running a frozen test verifies reproducibility; it is not permission to tune against it. Machine/runtime measurements can vary while the semantic results digest must match.

Historical compatibility:

```powershell
python scripts/run_experiment.py --scenario E7 --hours 24
python scripts/audit_phase_a_baseline.py --output results/phase-a-baseline-check.json
```

The latter reproduces standard scenario detection metrics after the fixes, but its live hashes and timings reflect the current implementation. The immutable pre-change measurements are [baseline.json](baseline.json). Archived hashes use explicit `sha256:`/`git:` prefixes to identify provenance rather than credentials; their digest values and measured results are unchanged. Archived JSON is a review snapshot; test-only execution uses the raw frozen artifact generated by the CLI, not the prefixed archive. A fresh checkout should use the full command to generate its own source fingerprint and validation record.

Repeatable complete-batch timing is available separately:

```powershell
python scripts/benchmark_phase_a.py --study results/phase-a --repeats 3
```

It uses the frozen models and final test seed's E7 frame, without fitting on that frame. It records wall time from in-memory input through alert generation and then through explanation/correlation. This benchmark does not select or alter a threshold.

## Independent sessions and leakage controls

| Role | Seeds | Duration | Usage |
|---|---|---|---|
| Training | 101 | 24 h | Original IF uses first 6 h; candidate IF uses full 24 h; NET uses first 6 h in both |
| Calibration | 202 | 24 h | Nominal candidate-score quantiles only |
| Validation | 203 | 24 h per case | Candidate selection and trade-off analysis |
| Final test | 301, 302, 303 | 24 h per case | Frozen comparison and robustness; no tuning |

All roles are disjoint deterministic RNG seeds. Each creates a fresh simulation and receives a content fingerprint. Timestamps reuse the simulator's relative 1 January schedule; they do **not** identify the same observations. Independent noise/command/event realizations still share the same physical simplifications and deterministic pass patterns. This is limited synthetic generalization, not independent spacecraft or mission validation.

Labels are created after nominal training/calibration and are never feature columns. Raw telemetry and trailing 60-sample mean/std form 21 numeric features; windows restart in each run, include only past/current samples and do not cross role boundaries. Missing/nonfinite values, unordered/duplicate timestamps and non-1 Hz telemetry are rejected by the research path rather than silently imputed. The legacy preview remains unchanged and overlaps its nominal training timeline; do not use its scores as held-out results.

## Selection history and frozen decision

The initial full-day fit plus nominal `.999` calibration reduced nominal validation FP seconds from 4,550 to 94, but lost all original ML-detected E5/E6/E7 thermal events. Although rules preserved hybrid coverage, that candidate was **rejected for promotion**. Its initial acceptance flag used the earlier hybrid-only criterion; this was tightened before testing. The original record is [rejected-calibration-999.json](rejected-calibration-999.json), not the chosen result.

Validation then compared quantiles `.95`, `.975`, `.99`, `.995`, `.999`. The reproducible selection chooses the **largest full-day-model quantile reducing FP while retaining every event detected by the original ML profile on validation E1–E7**. The selected quantile is `.975`. Selection therefore uses validation attack labels to assess coverage; threshold values themselves come from separate nominal calibration scores. No claim is made that validation is untouched evaluation data. Sample recall and delay are allowed to change and must be shown explicitly. Test seeds were first used only after this revision was frozen.

The exploratory two-model grid is [exploratory-grid.json](exploratory-grid.json); the complete selection is regenerated as `calibration-grid.json`. `.975` is an experimental setting, not a paper target or security guarantee. The calibrated profile is opt-in through the scientific CLI; it does not silently alter the deployed dashboard's established IF threshold.

## Metrics and ground truth

**Seconds:** every observation is a complete UTC 1 Hz bin. A second is positive if any explicit injected interval covers it, including E3's entire burst interval. Overlapping source intervals are unioned. Any alert observed in that second predicts positive; duplicate alerts and overlapping detectors count once. TP/FP/TN/FN therefore have the same denominator across methods. Ratios with zero denominators are JSON null / blank CSV, not invented zeros. Precision=TP/(TP+FP), recall=TP/(TP+FN), F1=2TP/(2TP+FP+FN), FPR=FP/(FP+TN). Alerts after the injection window, including rolling-feature tails, remain FP. Unrelated temporal hits can receive sample credit, which is why events are evaluated separately.

**False alarms:** report FP seconds per simulated hour and, separately, contiguous FP-second episodes per simulated hour. Episodes are broken by at least one unflagged or positive second. Both use total scored duration, including attacks, as exposure. Raw alert counts also remain available. Episode aggregation never replaces sample FP counts.

**Events:** the ledger names the injected source/domain and compatible detector(s). An event is detected only by matching evidence inside its inclusive interval: R1 for unauthorized commands, R2 for a flood, NET for traffic/peer injection, R3 or ML for thermal injection, SYS for explicit watchdog/degraded events. E7 has six source-matched events, including the two subsystem events. Event recall is detected/total events; delay is first matching observation minus injection onset, averaged over detected events only. Missed events have null delay. There is no invented universe of negative events and no event-level TN/FPR. E3 can have 1/59 second recall and 1/1 event recall simultaneously.

**Incidents:** evaluate correlation output separately. E6/E7 and the reordered variant are deliberately combined reference injections. A matched group requires supported evidence from at least two labeled domains. One reference incident cannot earn extra true positives from fragmentation; matched fragments and unmatched groups are reported separately. Precision describes emitted group support; recall describes reference incidents. Incident TN/FPR is undefined. The first *supported* association delay is the time a second matched domain becomes available minus the earliest injection—not a preceding background alarm. Temporal overlap does not establish cause.

**Latency:** simulation-clock detection and association delays are distinct from wall-clock processing. `processing.csv` records feature extraction, rules, NET, SYS, both IF profiles, explanation and correlation separately. Detection batch totals exclude generation, fitting and evaluation/reporting; they are not streaming end-to-end latency. `runtime.json` records fitting, whole command duration, sampled process RSS and hardware/software. RSS is sampled every 20 ms; it includes interpreter/data/evaluation and can miss short peaks. No uncontrolled before/after wall time is described as a formal speed benchmark.

## Comparisons and ablations

- Rules only (R1 correctness fix included), original IF, calibrated IF, NET only and SYS only show different scopes against the same ground truth.
- Original hybrid replays the old R1 primary-source exemption,6 h IF fit/.95 training threshold, NET and SYS. R3 formatting optimization is output-equivalent; its measured execution time is from current code, not the old row loop.
- Full-day uncalibrated hybrid separates the longer nominal fit from threshold calibration.
- Improved hybrid includes fixed R1, full-day IF/.975 independent calibration, unchanged NET/SYS.
- Without ML, without network and without rules retain the other components unchanged. Correlation is not treated as another raw detector.

Confusion counts are aggregated **within each scenario across independent seeds**. E1–E7 share each seed's nominal background; pooling their repeated negative seconds would inflate apparent sample size. No significance test or confidence interval assuming independent seconds is claimed.

## Robustness and preserved behavior

Standard E1–E7 injectors are unchanged. Additional cases change timing (09:00:30), intensity (known-peer traffic×2), duration (15s thermal), and ordering (thermal→network→command). Benign cases introduce 12 authorized commands, a new authorized peer, 25% network load increase and extra temperature/CPU noise. All magnitudes, durations and seeds are recorded in the protocol. The network detector is not given the experiment's authorization label; an authorized unseen peer is expected to reveal false alarms. Fixed-minute R2 can miss a burst split over a minute boundary. These stress cases are not added to the dashboard scenario catalog.

Trust retains the original family caps, severity weights, trailing window and correlation deduction. Reports include actual replay snapshots and subsystem states. **Operational Trust is an explainable prototype indicator, not a probability of compromise.** The UI is preserved; only its optional browser checker gains synchronization/whitespace handling while retaining every original assertion.
